# Перенос parser.market — отчёт о кандидате, 28.11.2026

**Статус:** реализация общего адаптера и тарификации в закрытом кандидате, не production. DeepSeek-only сохранён; рабочие Octoport и Мастерская не изменены.

## Реализация
- Проверены исходники действующего Octoport: dacb7114476cad88b34932ade4c03942a058060a; актуализация общей защиты квитанций по 180660c019e5a9fa530e5ec48c9e55724a93c3ae.
- Зарегистрирован parser-market (checks, parser-market-v1). Транспорт search/cards/reviews Ozon, схема запроса, устойчивые состояния заказов. Расчёт и все финансовые переходы используют существующие service_billing, coins, service_client_prices, service_attempt_prices и coin_attempts; отдельного кошелька нет.
- /admin/keys, /admin/services, /admin/finance: write-only ключ, тариф для клиентов, пакет/себестоимость, квота, баланс поставщика, остановка, возобновление, сверка, история расхода. Настройки и доступ контролирует сервер.
- Версия цены закрепляется при принятии заказа. Фактические проверки берутся из used_checks_total, а не из оценки глубины. При неизвестном исходе — сверка исходного заказа, не повторная покупка. Квитанции после исправлений не используются повторно.
- Единый типизированный API заказа доступен последующим предметным сценариям. Новых пользовательских экранов конкурентов и автономных платных инструментов помощника не добавлено. Приёмка CORE-DUAL-01 и ТЗ-МП-001 не закрыта.
- Сохранены изменения v34 (продажи Яндекс Маркета) и v35 (сезонное планирование). Фактическая версия рабочего сайта: c5927ce090a80cbd28cb701a7ba46a42a5f5f4ad.

## Проверки
| Набор | Результат |
|---|---:|
| HTTP и финансовый журнал parser.market на тестовом транспорте поставщика | 12/12 |
| Целевая регрессия ядра, прав, админки, Яндекс Маркета, сезонного планирования и DeepSeek-only до последнего усиления квитанций | 97/97 |
| Финальная перепроверка parser.market и общего биллинга после усиления квитанций | 31/31 |
| Контракт фактических JS/HTML форм на контролируемых ответах API, Chromium | 1/1 |
| Тот же контракт, Opera | 1/1 |

Наборы пересекаются, не суммируются как независимая полная регрессия. Пример из теста: цена 0,45 монеты, резерв за две проверки 0,9; подтверждена одна — списано 0,45. Изменение цены на 1,25 относится к следующему заказу. Себестоимость 0,2 за проверку не меняется. Финансовый тест отдельно подтверждает невозможность повторно использовать старый идентификатор после исправления квитанции.

Реальные оплачиваемые запросы: 0. Использован тестовый транспорт; живой ответ поставщика, связанный браузерный end-to-end и самостоятельное автоматическое исполнение заказа не приняты. Результат не является полной приёмкой нового интегрированного runtime.
