# layout-v7 — единое оформление Подмастерья
26.11.2026. Основа: 433c201cae5a82e1a7162ae3e03a31ddb4be4b7c.

## Причина
Шаги подтверждения входа из исходного Harness использовали классы octo-verification и public-auth, для которых в новом проекте не было соответствующей рамки и стилей. Тема этих страниц также не совпадала с настройкой кабинета.

## Исправления
- Общая шапка, центрированная карточка авторизации шириной до 424 CSS px, нормальные размеры полей и кнопок, адаптивное оформление, заметные ошибки.
- Вход, регистрация, привязка почты, подтверждение почты, завершение регистрации, подключение TOTP, повторный вход с TOTP, истёкшее подтверждение, страницы ошибок, возврат к кошельку.
- Единая тема из локальных настроек, системный режим, светлая и тёмная темы; общий внешний скрипт загружается до отображения страницы.
- Отдельная статистика администратора в общей зелёной палитре. Убраны неактивные элементы удаления аккаунтов: эти маршруты были отключены ещё в прежнем каркасе. Права и серверные ограничения не расширены.
- При прямом открытии регистрации создаётся гостевая сессия штатным запросом; кнопка разблокируется только после его успеха. Нет обхода проверки Origin или подтверждения почты.
- Стилизованы страницы навигационных ошибок без изменения JSON-контрактов API.
- Авторизация, одноразовые коды, лимиты, TOTP, сессии и расчётное ядро не изменены.

## Приёмка
Новый тест tests/browser/test_podmasterye_layout.py: 4/4, 77.012 с, 229 файлов снимков экрана. Публичные страницы, 18 вкладок кабинета, админка, статистика, форма пополнения, подтверждение входа и ошибки. Размеры 1440 и 390 CSS px в обеих темах; дополнительно 320 px для ряда публичных и служебных страниц. Проверены границы элементов, ширина документа, доступность форм и отсутствие JS-ошибок. Вручную просмотрены контрольные скриншоты. Сценарии всех состояний подтверждения проверены на презентационных фикстурах; регистрация, неверный/верный код, выход и вход администратора с настройкой TOTP — на настоящем локальном сервере и синтетической почте.
Первый прогон выявил отсутствие гостевой сессии при прямом открытии регистрации, исправлено. Последующий сбой относился к ожиданию навигации в тесте выхода; исправлено ожидание. Итоговый прогон успешен.

Прежний функциональный браузерный набор: 14/14, 81.575 с. Он завершён до последнего исправления создания гостевой сессии; последнее исправление напрямую покрыто новым успешным сценарием регистрации. Повторный полный серверный прогон учёта в этом проходе не выполнялся: расчётные модули не изменялись.
Все испытания без реального DeepSeek, ключей маркетплейсов и платежей. Доставка реальной почты, восстановление доступа через отдельный UI (его нет), а также реальное пополнение не проверялись. Результат не означает тестирование каждого возможного пользовательского ввода.
