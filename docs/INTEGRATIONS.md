# Интеграции и собственный API — проект
Два механизма: pull API маркетплейсов и push API внешних магазинов. Ozon Seller/Performance, WB, далее Яндекс Маркет; проверять фактические права и доступность каждой метрики. Переиспользование наработок Octoport после аудита, не подключать чужие рабочие ключи автоматически. Отдельные ключи для каждого внешнего источника, права, ротация, отзыв, защищённое хранение, аудит без секретов.

Входящие события: заказ создан/изменён/оплачен/доставлен/отменён/возвращён, финансовое начисление/комиссия/логистика/эквайринг/выплата, приход закупки, выпуск продукции. Чтение каталога/остатков/себестоимости по разрешённым scopes. Стабильные source_id, external_order_id, line_id, event_id, version, timestamps, валюта, qty, price и тип операции. Уникальность в границах tenant+source; одна строка заказа не должна конфликтовать с другой витриной. Idempotency, повтор после таймаута, out-of-order, исправление, частичный возврат, раздельный факт оплаты и реализации; сверка с финансовыми отчётами. Отложенная привязка артикула: неизвестный SKU в очереди, связать с внутренним изделием и обработать ранее поступившие события ровно один раз. Автоимпорт и синхронизация без ИИ, статусы и причины ошибок. По умолчанию не изменять данные на маркетплейсе.

Обычные магазины: документированный HTTP API с ключом; в будущем адаптеры WooCommerce, Tilda, 1С-Битрикс, МойСклад, 1С, кассовых систем, Telegram/MAX и самописных магазинов. Доступность и права каждого внешнего API проверять отдельно. Не считать наличие вебхука подтверждением полной интеграции. Поддержать ручную продажу. Тестировать только на отдельном магазине/контрольных данных по разрешению. Сравнение конкурента — S14.
