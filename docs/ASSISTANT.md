# Помощник — фильтр, матрица, экономичный исполнитель

Требование владельца: сложность вопроса не определяет необходимость вызова ИИ. Даже сложные объяснения формул, работы склада, различия прибыли/денежного потока, интеграций и планирования закупок должны по возможности покрываться матрицей проверенных знаний. Матрица — не только список команд.

## Граница первой версии
Помощник, фильтр, матрица, провайдер DeepSeek и валидируемый исполнитель входят в фундамент, а не добавляются после SEO-этапа. Предлагается лёгкий специализированный исполнитель без автономного планировщика и полноценного многодиалогового чата. Новая функция регистрируется как типизированная операция с параметрами, правами, UI-действиями и FAQ/шаблоном; отраслевой модуль расширяет общий каталог и скрипты. Не строить универсальный агент или сложную платформу плагинов заранее. Публичный калькулятор может считаться без обращения к модели; помощник при этом доступен в первой рабочей версии продукта. Схему reuse Harness проверить по актуальному коду.

## Маршрутизация
1. Нормализация запроса, контекст мастерской, страницы, выбранной сущности, фильтров, ролей, ожидаемого уточнения. Ключи не передавать модели.
2. Дешёвый локальный фильтр тематики и намерений: словари синонимов, точные/лексические совпадения, BM25 как кандидат, контекст, отрицательные примеры. Не классифицировать по одному слову. При неоднозначности уточнять.
3. Однозначный маршрут: FAQ → проверенный текст; UI → типизированная команда; read → скрипт+шаблон; write → валидируемый handler. Ноль LLM. Составные запросы допускают несколько известных операций без LLM, когда параметры однозначны.
4. Отсутствуют параметры → форма/шаблон уточнения; сохранять заполненные поля. Не подставлять неизвестное как 0.
5. Не распознано → DeepSeek получает вопрос, минимальный контекст и только релевантные схемы матрицы. Выбирает структурированную операцию и параметры. Не исполняет SQL, не пишет произвольный код, не рассчитывает финансовые показатели.
6. Сервер проверяет схему, права, владение, версию, лимиты, предусловия. Подтверждение опасных действий независимо от модели. Транзакция и результат с фактами, кодом ошибки. Ответ по шаблону и UI-обновление; второй LLM-вызов только при необходимости анализа.
7. Сложная аналитика: скрипты готовят декомпозицию, факты, допущения; шаблон если достаточен, LLM только для интерпретации. При сбое модели UI и безмодельные маршруты продолжают работать.

## Контракт матрицы
ID, namespace, intent (faq/ui/read/write/analysis), purpose, синонимы, негативные примеры, context, JSON-schema параметров, handler/knowledge-id, permission, confirmation, ambiguity policy, result schema, template, UI actions, version, tests. Справочные ответы с источником/версией формулы и примерами, обновлять атомарно вместе с изменениями бизнес-логики. Начальная TSV — заготовка, не исполняемый каталог. Дальнейшая разработка: автоматические проверки ссылок handler/FAQ/UI/тест, покрытие всех функций, версионность, админ-редактор шаблонов.

## UI
navigate, set_filter, select_entity, open_form, fill_form, highlight_metric, render_report, show_confirmation. Только белый список путей и полей, без произвольного JS/DOM. Заполнение формы не равно записи. Успех только после commit, изменения сразу отражаются в кабинете. При конфликте версии — показать актуальное состояние.

## Экономия
Метрики: маршрут, ID/версия шаблона, число вызовов, input/output/cache tokens, модель, фактическая стоимость, задержка, результат, уточнение. В админке доля zero-LLM, p50/p95 стоимости/времени, промахи фильтра. Не обещать процент экономии без эталонного корпуса. Префикс-кэш стабильных релевантных схем без секретов, не отправлять всю БД/историю. Ограниченный retry, при отказе причина и безопасная альтернатива. Расширять матрицу по промахам с независимой проверкой и тестами. Не вводить автогенерируемые команды без проверки.

## Примеры
«Почему закупки вычтены из денег, но не из прибыли?» — FAQ о запасах; 0 LLM. «Открой продажи за прошлый месяц и выдели убыточные товары» — типизированные UI/отчёт, 0 LLM при однозначном совпадении. «Бусины по 400 в пачке, расход 40 на браслет» — атомарная связка материал/упаковка/норма, уточнить неоднозначное изделие и неизвестную цену. «Почему упала прибыль?» — детерминированный отчёт причин, затем при необходимости LLM.
