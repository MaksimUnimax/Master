# Реализованная матрица помощника — сверка с ТЗ

Проверено по исполняемому коду v9/v10, а не только по исходному docs/ASSISTANT.md.

## Каталог
platform_core/podmasterye_matrix.json — 100 записей: FAQ 23, UI 21, report 23, specific 3, form 30. Всего 222 алиаса. matrix/accounting.tsv — читаемый экспорт каталога. Версия accounting-v3. Поля: ID, intent, aliases, page, answer / view / metric / op, pattern и defaults там, где применимо. Типизированные формы получаются из book.FIELDS и agent_forms.EXTRA (28 учётных операций + 7 вспомогательных групп, 161 объявление поля). Это две связанные, но разные части: матрица выбора маршрута и каталог инструментов/форм.

## Фактический алгоритм
1. domain.decide проверяет сессию, принадлежность чата, мастерскую, idempotency requestId и formContext.
2. Если нет formContext, matrix.route нормализует регистр, ё/е, пробелы и конечную пунктуацию. Поиск по точному алиасу; затем по алиасу с суффиксом периода (сегодня/вчера/месяц/последние 30 дней/всё время); затем три специальных шаблона материала и regex заполнения отдельных операций. Материал выбирается однозначно по имени или ограниченному лексическому совпадению одного слова. Неоднозначность специального шаблона вызывает локальное уточнение.
3. FAQ выдаёт проверенный текст. UI открывает раздел. report/specific вызывают book.report и возвращают факты, период, выделение метрики. form готовит черновик. Это ноль вызовов LLM. Есть отдельное устаревшее узкое полное регулярное выражение рецептуры: оно вызывает _save непосредственно после серверной проверки, а не открывает форму. Нельзя считать все записи одинаково подтверждаемыми через UI.
4. Если запрос не найден либо передан formContext, route=model. DeepSeek получает контекст Harness и 7 зарегистрированных инструментов (production_state, accounting_report, prepare_accounting, form_catalog, current_form, prepare_form, prepare_recipe). Схемы общие, каталог полей выдаётся отдельным инструментом по запросу. Сервер проверяет grant, сессию, роль/доступ, принадлежность, допустимые поля, типы, сущности. Черновик не проводит финансовую операцию; пользователь подтверждает её через штатную форму. Итоги расчётов только программные. Секреты и ключи интеграций не входят в данные этих инструментов.
5. pm_turns сохраняет маршрут и результат, локальные ответы содержат matrixId/matrixVersion. Платные вызовы записываются в отдельные usage_operations, coin_attempts и журнал; admin-only квитанции и админ-агрегаты показывают фактические токены и подтверждённые расходы.

## Не завершено по исходному ТЗ
Нет общего многоуровневого фильтра тематики/намерения с BM25, негативными примерами и калиброванным порогом/отрывом кандидатов. Нет универсального разбора составных запросов в несколько локальных операций. Нет локального продолжения произвольной формы по formContext (пока model). Нет отбора только релевантных схем перед DeepSeek: доступны все 7 инструментов. Нет отдельного редактора матрицы, панели долей локальных маршрутов и промахов, p50/p95 затрат/задержки, полноценного отчёта по эталонному корпусу и проверенной политики префикс-кэша. Поэтому 100 записей нельзя считать полной реализацией фильтров из ТЗ или доказательством процента экономии.

## Примеры
«Как считается себестоимость?» → A-F01, FAQ, 0 LLM. «Покажи чистую прибыль за прошлый месяц» → A-R01 + период + book.report, 0 LLM. «Сколько бусин осталось?» → A-R13, поиск материала, 0 LLM. «Купил бусины 2 пачки за 1600 рублей» → A-W04, черновик закупки, 0 LLM при совпадении. Произвольное дополнение формы → DeepSeek + current_form/prepare_form, расходы по фактической usage. Реальные расходы не оценивать из тестовых имитаторов.
