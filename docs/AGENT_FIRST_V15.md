# Agent-first: matrix, native context and navigation

Authenticated member: the matrix is an optional deterministic shortcut. Complete matches may answer or prepare a draft without a model call. Every miss, conditional or unresolved intent falls back to the ordinary Harness agent. No member subject allowlist and no heuristic removal of capabilities. Guest scope and quotas remain separate, through inherited guest selector. Service FAQ cards use the shared published source; no arbitrary guest dialogue is enabled.

Context: local user/assistant pairs are immediately published in the native Harness session via localExchange using the existing event writer. Request IDs are immutable and replay-safe. The pre-model synchronization also recovers missed local publication. All provider calls use the same full stable set of seven safe MCP tools, with compact operation identifiers and authoritative field schemas obtained on demand. Exact data and financial calculations remain server-side; operations require confirmation. Model context reads the existing native event log. File handlers and separate per-service storage remain unchanged.

Native Harness 0.2.2-rc.1: mount dsh-token-meter, dsh-compaction-tool-result-pruner, dsh-compaction-basic. Initial policy thresholdRatio=0.04 (40k tokens for a million-token window), retainTokens=8000, headroomTokens=8192, summary maxTokens=2048, one context-overflow recovery. These are initial tuning values, not a proven optimum. The native compaction checkpoint is filtered out of public UI projections, not the durable native journal or model context. Compaction calls use the existing grant, metering, and provider. No separate memory, custom summarizer or extra paid selector. Prefix cache hits are provider usage receipts, not a guaranteed discount. Stable tool/system contracts were verified with local provider fixtures; live cache performance is unverified.

Navigation: independent left rail and assistant/work surface state. On narrow layouts the rail occupies a grid column and shifts content; selecting a page keeps the rail open and shows the work surface. Desktop and mobile assistant restore retain the conversation/draft.

Acceptance: 15 existing server scenarios, 3 new server scenarios (local/model chronological transcript, strict guest scope, native compaction with synthetic cache usage), 2 browser scenarios. All passed after fixing compact-checkpoint projection. The compaction pressure test used 12 durable exchanges, verified the summary call and its settlement, and preserved all 24 visible messages. Provider and audio costs use fixtures; no live DeepSeek charges. Deployment only after source and test verification.
