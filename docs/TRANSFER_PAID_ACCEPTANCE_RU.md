## Разделение доступа и расходов

Первый preflight остановился на optional admin status с HTTP 401, ещё до
первой фазы: 0 provider attempts и 0 расходов. Штатная startup-миграция
`AccountAccess` отозвала старый административный session без MFA proof.
Это правильное действие защиты. Авторизация не ослаблялась, обходной
административный session не создавался. Основной сценарий повторён без
необязательного admin-параметра с действующим собственным member session.

При неопределённой стоимости скрипт прекратил бы дальнейшие dispatch,
не снимая reserve и не повторяя платную попытку. В этом прогоне такого
состояния не было. Защита источника/PID, bounded wallet, счётчик attempts и
read-only ledger зафиксированы в `docs/acceptance/live-r3.json`.
