### Что доказано общей регрессией

Сохранены прежний guest classifier/local FAQ/calculators, снятые квоты,
перенос истории при регистрации, три колонки, темы и responsive layouts,
учёт материалов/рецептур/склада/закупок/выпуска/продаж/расходов/задач,
импорт/выгрузка, файлы, document creation/edit, native context/compaction,
streaming/stop/recovery, обязательная защита админа и штатный checkout.
File/media parse выполнялся с действующей Linux Landlock-защитой на Alisa.
Внешние model/recognition/payment/TG transports в регрессии управляемые;
реальные внешние вызовы перечислены отдельно, не смешаны с fixture PASS.

Новые проверки охватывают точные coins, отрицательные дробные остатки,
агрегаты больше SQLite INTEGER, конкурирующие reserves, known-zero и unknown
cost, независимые customer/supplier prices, priceVersion/FX snapshots,
receipt conflicts, атомарную сверку и payment recovery. Повторное предъявление
квитанции не создаёт новое списание. Поиск/фильтры/пагинация выполняются
сервером, пользователь не видит административную себестоимость другого scope.

Расписания используют прежний durable timer: один захват, lease/fencing,
восстановление после рестарта, one-shot/daily/weekly/monthly и часовые пояса.
Шесть отчётов считают данные локально. Подтверждённое хозяйственное действие
проходит общий учётный finalizer; устаревшее или отозванное разрешение
отклоняется. Result и app/TG delivery хранятся независимо, unknown delivery
не объявляется успешной и не повторяется вслепую.

## Исправленные дефекты и честность тестов

Исправлены перекрытие меню аккаунта sticky-заголовком, потеря обычного
file-only сообщения при проекции истории, stale authority после архива
мастерской, возрождение старого timer authority после restore и отсутствие
точного общего форматирования баланса на части admin экранов. Обычное пустое
user message сохраняется для последующего attachment enrichment; только
серверный system exchange не добавляет фиктивного пользователя.

Тесты не исключались ради успеха. Старые контракты «Подмастерье» как бренд
сайта, целочисленный видимый balance, отсутствие OR и девять MCP tools
приведены к ТЗ: «Мастерская», сотые, оба провайдера и 11 точных MCP tools.
Unknown-provider fixture ищет marker внутри native-prefixed context, сохраняя
строгие 409/reserved/ровно 1 attempt. Mobile resize fixture ждёт фактическое
закрытие навигации после breakpoint, без sleep/force click. Для generic
service billing из 55 исходных assertions 54 сохранены без изменения после
переименования только fixture-service; одна проверка известного subtotal перемещена в
`knownProviderRub` и усилена проверками `providerRub is None`, incomplete и
одной unknown attempt. Добавлены три assertions. Денежные и квотные значения
не изменены.

Диагностические прогоны сохранены отдельно. Локальный kernel возвращал
Landlock ENOSYS; parser sandbox не отключался. На Alisa добавлены отдельные
pinned fixture dependencies для DOCX/PPTX/PDF, без изменения рабочего runtime.
Первоначальный clean test launcher выбирал legacy engine; это исправлено
явным production `native` flag, после чего полный набор повторён. Ошибка
длины UNIX socket устранена коротким отдельным TMPDIR браузера. Неуспешный
или прерванный диагностический прогон не назван финальным PASS.

Для самостоятельной фиксации command/environment/source bindings native-набор
повторён на Alisa. Первый launcher не указал `HARNESS_TEST_PYTHON` и выбрал
системный Python без `referencing`: два fixture-сценария завершились ошибкой.
После указания прежнего закреплённого venv все неизменные 77 проверок прошли;
617 файлов до и после совпали. Диагностический log также сохранён.

Отдельно сохранён полный Opera headless-прогон: 259 PASS и один FAIL проверки
wheel-прокрутки. На независимом минимальном HTML та же Opera не прокручивала
все шесть вариантов контейнера, хотя wheel попадал в правильную цель и не
был отменён. В настоящем окне через Xvfb шесть вариантов и неизменный исходный
тест прошли. Финальный полный Opera gate использует этот оконный режим;
CDP-команда wheel, порог прокрутки и остальные assertions сохранены.

## Миграции и восстановление

На реальной readonly обезличенной копии проверены 4 DB и 101 существующая
таблица с исходными столбцами. Девять версий миграций применились, повтор
initializer/open и восстановление дали те же fingerprints. Native история:
один chat, 14 видимых сообщений. SHA пяти исходных рабочих файлов совпали
до и после backup/migration; исходная production база не изменялась.

В снимке не было материалов/продуктов/движений. Поэтому сохранность
наполненного хозяйственного учёта дополнительно доказана synthetic regression;
нулевые production counts не выдаются за проверку большого реального учёта.
Raw базы, тексты, токены и ключи в исходники, публичный export и ZIP не входят.
Закрытая эксплуатационная backup-точка на Alisa имеет отдельную metadata;
новая согласованная backup непосредственно перед будущим переключением
остаётся обязательной. Порядок полного restore описан в миграциях/runbook.

Закрытая полная backup/restore отдельно выполнена 27.11.2026 в 16:50:47 UTC+5:
9 state files, 4 конфигурационных файла и действующий environment Мастерской,
4 SQLite, 101 таблица, 190 строк. Сохранены её собственные auth/encryption/provider
keys. Fingerprints источника до и после снимка совпали; integrity/FK и restore
в отдельный каталог прошли. Процесс не останавливался, приложение из копии
не запускалось, данные Octoport не копировались. Каталог имеет права 0700,
архив — 0600 и владельца root. Raw backup и индивидуальные хеши секретных
файлов остались только на Alisa. Безопасные metadata:
`acceptance/closed-backup-report.json`.

## Выпуск и оставшиеся условия

Полный canonical Git tree, bundle, git delta, source manifest, code provenance,
схемы/миграции, API/runbooks, machine-readable матрица, logs, выбранные UI
доказательства и ledger расходов включены в один архив. Git delta предназначена
для ревью; сопровождение и установка используют целое исходное дерево.
Публичная часть поставки ограничена проверяемым авторским слоем; факт публикации
и публичный commit отражены в `release.json`. Приватное ядро
не публикуется вопреки его действующему правилу конфиденциальности.

OR/image credentials и compatibility, Telegram target, свой Metrika counter,
боевой checkout/fiscal approval, политика удаления, private GitHub remote и
внешний D0 остаются точными самостоятельными границами. Блокеры не превращены
в фиктивный PASS. Production, DNS/Nginx/TLS и рабочая почта не переключались.
