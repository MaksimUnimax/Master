# Внешние границы приёмки v31

Эти пункты не получают статус PASS на основании controlled transport или
наличия файлов в коде. Они не мешают проверять остальные части единого
кандидата. Код и данные работающих сервисов в рамках этой разработки
не переключались.

| ID | Требования | Что уже проверено | Что ещё требуется |
| --- | --- | --- | --- |
| B01 | AI01–AI04, T13–T15 | Общий DS/OR router, free/paid catalogue contracts, права, тарифы, streaming/stop/context/cache/tools, recovery, write-only keys и monitor | Собственный ключ OpenRouter Мастерской и реальная совместимость каждого разрешаемого model/purpose. В существующем собственном key directory OR отсутствует. Непроверенные модели не включены как совместимые. |
| B02 | AI08, T20 | Встроенный image path, стоимость, версии, scope/download, cancellation и unknown/recovery на управляемом provider transport | Реальный доступный генератор и подтверждённые тарифы/совместимость. Внешний платный image call не выполнялся. |
| B03 | AI04, TM04, T15/T24 | Одна Telegram binding, app/TG/both, отдельные статусы, dedup/rearm, revoke/unknown; настоящая native публикация в основном чате | Подтверждённый тестовый адресат и собственная действующая привязка для живой доставки. Вне изолированных fixtures сообщения адресатам не отправлялись. |
| B04 | AD02, T29 | Согласие/отказ/отзыв, один public SPA hit, запрет private/admin, отдельная конфигурация и hostname gate | Собственный счётчик/токен Метрики, согласованные постоянный domain и правила аналитики, живой отчёт посещений. Сбор по умолчанию выключен. |
| B05 | AD01, T28 | Checkout, receipt email, amount handoff, идемпотентное начисление и административная сверка через штатный verifier | Собственный магазин, фискальная конфигурация/юридические данные и отдельный допуск на фактический платёж и чек. Реальная оплата не включалась. |

Доступный Master публичен; его `foundation/README.md` запрещает публикацию исходников Octoport. Подключённый GitHub API позволяет менять файлы/ветки, но не создаёт repository; в доступном браузере нет авторизованной сессии. |

Поиск прежних решений владельца не обнаружил утверждённой production-политики
необратимого удаления или отдельного разрешения на реальный платёж ЮKassa.
Ранее выданное разрешение платных DeepSeek Search/Fetch использовано только
для ограниченной изолированной проверки; оно не трактуется как допуск
к платежам покупателей, удалению данных или внешней рассылке.

Этот перечень не содержит скрытых выключенных «готовых» функций: статус
каждого критерия находится в основном ТЗ и machine-readable матрице.
Для новой внешней проверки используется тот же принятый runtime commit;
изменение runtime требует повторной регрессии затронутой общей сборки.
